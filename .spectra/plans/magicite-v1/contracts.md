# V1 shared contracts and decisions

Status: implementation proposal, frozen with this spec packet; no runtime contract has changed yet. All `[DECISION]` items are planning defaults chosen to make slices executable. An implementing agent may propose an amendment with evidence; it must not silently change a consumer contract. Normative requirement IDs live in each slice and the aggregate acceptance file.

## C0 — Product boundary and authority

[DECISION] Stable V1 is a local governed skill registry/router/composer. Host execution remains outside Magicite. Nonadaptive dense routing is the initial incumbent; hybrid must earn promotion. `experimental` is an explicit opt-in policy family. Routine route/search calls neither update authored artifacts nor persist evidence. Stable ranking ignores strength, usage, learned edges and Dream output.

Authority order for implementing this release: user task → this packet's shared contracts and frozen acceptance criteria → slice text → pinned source code for existing behavior → dossier and historical specs for context. Existing product behavior remains authoritative until the relevant implementation merges. Do not silently reinterpret historical `v1` design notes as GA claims.

Three durable domains are distinct: authored registry artifacts; governed local control state (approvals, audit, trust decisions, policy activation); and privacy-managed evidence. SQLite retrieval indexes remain rebuildable projections. Rebuild must never erase the latter two domains. All new persistent operations participate in the existing writer lease/fencing discipline; no second lock system.

[DECISION] V1 distribution remains one Python package and stdio MCP server. No remote service, marketplace, automatic skill synthesis, multi-writer learned-state merge, mandatory large reranker or cloud dependency.

## C1 — Engram 1.0 and asset envelope (owner S02)

Keep `.egr.md` with YAML frontmatter plus inline Markdown as the canonical default. The dossier's external `procedure.md` is optional, not a forced format conversion. Authoritative fields:

| Field | Type and semantics |
|---|---|
| `spec` | Literal `engram/1.0`; distinct from artifact revision |
| `id` | Existing stable engram ID; migration preserves it |
| `name`, `version` | Nonempty name; existing integer revision semantics retained |
| `intent` | `does`, `use_when`, `not_when` strings; routing text, never permission |
| `compatibility` | Optional constrained environment dimensions; missing dimension means no authored constraint, not a satisfied missing host fact |
| `capabilities` | `requires`: typed host or artifact prerequisites; `produces`: artifact capabilities only; `alternatives`, `conflicts_with`: explicit engram ID references |
| `relations` | `requires`, `before` and `supersedes`: arrays of exact engram references; semantics below |
| `risk` | Structured filesystem, subprocess, network, secrets requirements, consumed by local policy |
| `routing` | Positive/negative terms plus normalized body digest; no learned weights |
| `origin` | Authorship/import source descriptors and content hashes; no author-controlled local trust |
| `assets` | Optional relative path → SHA-256, byte length, media type descriptors |
| `extensions` | Namespaced object values preserved losslessly; unknown required extension rejects activation |

Retain provenance and lossless imported SKILL.md payloads, comments and unknown optional extension data. Existing frontmatter state retained for compatibility must be namespaced legacy metadata, never applied to stable ranking or trusted from imported files. S02 publishes exact JSON schemas and golden examples before S03/S04 integrate.

[DECISION] Version constraints have an explicit scheme: `{scheme: semver|pep440, range: string}`. Languages/frameworks/package managers each use normalized lowercase keys; no ambiguous cross-ecosystem range guessing. V1 SemVer grammar supports conjunctions of `< <= = >= >` comparators separated by commas, exact `major.minor.patch` versions, and normal SemVer prerelease ordering; excludes `^`, `~`, wildcard and OR syntax. PEP 440 uses standard specifier semantics and prerelease rules. Unsupported schemes or invalid ranges reject the artifact. OS vocabulary: `linux`, `macos`, `windows`; host IDs are opaque stable IDs supplied by the host. Tool and capability IDs are case-sensitive namespaced strings. A required capability reference is `{kind: host|artifact, id: string, version?: constraint}`. A produced capability is `{kind: artifact, id: string, version?: exact_version}`; skills cannot produce host grants or environment facts. Produced capabilities have an exact version when version-constrained consumption is expected. A missing `kind` in a 1.0 artifact is invalid; 0.2 migration must not guess a typed capability from prose.

Normative relation representation: `relations.before` and `relations.supersedes` contain `{id: stable_engram_id, version: integer_revision}` references. `before` orders two already-selected nodes and never causes selection; an absent target is inactive, while a selected wrong revision is an invalid reference. `supersedes` records replacement lineage and, when both exact revisions occur in one plan, makes that plan conflicting; it never silently rewrites a selected ID or grants trust to a replacement. Removing old routability is a separate reviewed lifecycle action. Legacy `depends_on` migrates to an explicit required engram reference under `relations.requires` with `{id, version}` pinned from the migration snapshot; missing/ambiguous targets are migration diagnostics that prevent a valid composed plan. `relations.requires` always adds the exact referenced prerequisite subject to eligibility. Legacy `composes` lacks typed normative semantics and stays in the legacy namespace until reviewed; migration must not invent `before`/`supersedes` from learned edges. S02 publishes the relation schema/fixtures; S08 consumes it.

Risk vocabulary: filesystem `none|read-project|write-project`; subprocess `none|declared-tools` plus tool IDs; network `none|optional|required` plus destinations; secrets `none|redacted|raw`. Broader/custom requirements require an explicitly understood extension; they cannot be mapped to a permissive default. Optional network is not a hard requirement unless the requested variant needs it. Risk describes requested effects, never permission grants.

Asset rules: resolve beneath registry root; reject absolute paths, `..`, symlink escape, duplicate normalized paths and digest mismatch. No remote fetch during parse, route or composition. Asset digest covers raw bytes; metadata digest uses canonical sorted JSON without signatures or runtime state. Authored external resources are included in registry snapshots and bundles. No body-content normalization that destroys imported bytes.

## C2 — Route context and eligibility (owner S06)

`RouteContext/1`: languages/frameworks/package_managers map names to exact version or null; platform; host `{id, version}`; capabilities; allowed_tools; permission grants; optional task-artifact capability inventory. Absent/null facts are **unknown**, not wildcard permission. Empty lists mean explicitly none. Request-provided grants may narrow server policy and can never widen it. Context is host assertion, not independently attested environment truth.

Eligibility is tri-state internally: eligible / ineligible / unknown-required-context. Any authored mandatory host/environment requirement with an unknown fact is excluded with `context_required`; unconstrained artifacts remain candidates if local policy allows. All dimensions are conjunctions; alternatives within an enumerated dimension are disjunctions. Lifecycle, quarantine, local trust, version, tool and risk checks precede scoring or body disclosure to any reranker. Artifact prerequisites are different: absence of an artifact capability does not make a candidate ineligible before planning. Eligibility reports `unsatisfied_artifacts` for C5 to resolve from eligible producers. Task-artifact inventory `[]` is known-empty; an omitted inventory is unknown and cannot be assumed to contain anything. With unknown inventory, C5 may satisfy every prerequisite through explicit producers; unresolved requirements return `context_required` rather than invented presence. Host/tool/risk facts remain immutable requirements and can never be satisfied by adding a skill. Filter again before returning a composed plan. New constraints are not silently bypassed for old clients; return abstention plus missing context fields.

Compatibility result: `{engram_id, eligible, reason_codes[], missing_fields[], unsatisfied_artifacts[], policy_digest}`. Stable codes include `quarantined`, `lifecycle_blocked`, `untrusted_origin`, `signature_invalid`, `version_mismatch`, `platform_mismatch`, `host_mismatch`, `tool_denied`, `risk_denied`, `context_required`, `asset_invalid`, `conflict`. Denied bodies and sensitive local paths are absent from explanations. Local artifact authorship may be allowed by explicit default local policy; imported signatures alone never allow routing.

## C3 — Candidate generation (owner S05)

Pure `generate(query, snapshot, config) -> CandidateBatch/1`; `snapshot` includes schema, registry content digest, policy-independent index generation, embedder identity/digest and tokenizer identity. Query is ephemeral. Default lexical index is rebuildable SQLite FTS5 BM25 over title, intent, triggers and body; if FTS5 is unavailable, report an explicit capability error or configured dense-only fallback. No silent ranking-mode switch.

[DECISION] Keep dense, sparse and trigger components observable. Each yields at most 100 candidates (configurable bound 1–1000); union is deduplicated by stable ID. Reciprocal-rank fusion uses sum of `1/(60 + rank)` across participating lists, with ranks starting at 1. Sort ties by stable ID. No extra trust/usage bonus. Negative triggers are evidence/relevance features, never replacements for hard compatibility or trust filters. Triggers cannot bypass eligibility. Bounded body chunks use deterministic tokenizer/chunk config and content hashes; aggregation uses max chunk relevance per artifact to avoid rewarding long bodies merely for chunk count. Publish truncation counts.

The orchestrator passes an eligible-ID mask to generators where supported and applies the same predicate after union; no top-k leakage of denied artifacts. Filtering must not starve retrieval: fetch additional eligible candidates up to a configured scan budget, or explain `candidate_budget_exhausted`. S05 tests standalone with an all-eligible mask; S07 wires the real predicate.

`Candidate/1`: ID, revision, source ranks/scores, fused score, body/asset digest, snapshot ID. Scores are not probabilities. Optional reranker interface takes eligible candidates only, at most 20 by default, an explicit local model ID/digest, token budget and timeout. No reranker is required for GA. Timeout/error follows configured incumbent fallback and records that choice; it must not silently change the policy ID.

## C4 — Route decision and explanations (owner S07)

`RouteDecision/1` fields: schema_version, decision_id, status (`selected|abstained|error`), selected IDs, ordered eligible candidate slate, bounded exclusion summaries, score components, confidence `{value: number|null, calibration_id: string|null}`, reason_codes, missing_context, truncation flags, policy_id/digest, registry/schema/config/model/tokenizer digests, selected content digests, selection mechanism and propensity, explanation version. The semantic portion is deterministic for pinned inputs; opaque decision IDs and timings are excluded from equality checks.

[DECISION] Initial incumbent is `dense-v1`. Before final evaluation, select the strongest simple safe policy among dense/sparse/trigger baselines on development data and freeze it as the release incumbent. Another simple policy can therefore replace dense through the same mandatory reviewed activation API. Candidate `hybrid-rrf-v1` is promoted only under evaluation.md; failure retains that frozen simple incumbent, not necessarily dense. A stable request never implicitly opts into adaptive behavior. Top-level policy identity fingerprints fallback behavior too. Abstain on no eligible candidate, unmet context, threshold/margin rejection or unsafe composition. Errors cover corrupt indexes or unavailable explicitly required models; do not disguise operational failure as confidence abstention.

Abstention thresholds are fitted on calibration split only; confidence remains null when no compatible calibration artifact exists. Calibrated abstention may only claim calibrated quality with a matching calibration digest. Deterministic selection has propensity 1 for the selected action and 0 for other actions under that policy; do not invent propensities from similarities. Exploration requires an explicit stochastic policy with logged action probabilities.

Return structured untrusted-content sections distinct from policy metadata. A route explanation is available in the normal result; no new tool count is mandated. S11 owns public schema wrapping and legacy field projection. Payload defaults: 20 candidates, 20 exclusion summaries, 64 KiB explanation JSON; body budgets remain explicitly configured. Explain every truncation rather than dropping a mandatory prerequisite silently.

## C5 — Typed composition (owner S08)

Pure `compose(selected_ids, context, snapshot, limits) -> Plan/1`. Normative edges (`requires`, `produces`, `before`, `conflicts_with`, `alternatives`, `supersedes`) are distinct from explanatory provenance and experimental learned affinity. Learned edges never supply mandatory dependencies.

Host-kind requirements must already pass C2. Resolve artifact-kind requirements using known context inventory first, then eligible producers. A known-empty inventory plus consumer B requiring artifact X and eligible producer A producing X must yield A→B; it must not filter B out before planning. Unknown inventory never supplies a capability without evidence. `relations.requires` expands exact engram prerequisites; `relations.before` orders selected nodes; `relations.supersedes` is replacement lineage with pairwise conflict semantics per C1. Multiple producers require an explicit selected alternative or a deterministic policy preference; otherwise return `ambiguous_provider`. Version-unsatisfied dependencies, conflicts, dangling mandatory references and cycles return an invalid plan with diagnostics; never return a partial plan marked executable. Optional alternatives must be labeled optional. Stable Kahn topological sort breaks ties by ID. Default limits: 16 nodes, 32 normative edges, depth 8; exhaustion produces `budget_exceeded` with no executable prefix.

`Plan/1`: status (`valid|invalid`), nodes with immutable content/asset hashes and untrusted procedure references, typed edges, topological order, supplied/missing capabilities, requirements/risks, diagnostics, snapshot and policy IDs. `valid` means structurally valid under provided facts; only a separate host verifier can attest successful execution. Restored/superseded artifacts are rechecked against current policy. No runtime subprocess or network invocation by planner.

## C6 — Evidence and privacy (owner S09)

The retrieval plane can buffer a bounded decision receipt in ephemeral state. Durable persistence occurs only through an explicit governed evidence checkpoint under the writer lease. No background per-route persistence hidden in logging. Crash before checkpoint loses unacknowledged receipts; document that RPO. Checkpoint acknowledgement means durable commit; retries use event IDs and cause zero duplicate effects.

[DECISION] Evidence is a separate authoritative local ledger under the data directory, outside the disposable retrieval database. Versioned records are append-only between retention/deletion operations; segment manifests/checksums and explicit deletion tombstones reconcile append-only audit with privacy erasure. Rebuild consumes authored artifacts and preserved control/evidence domains, not vice versa. The exact file/segment layout belongs to S09, but atomic receipt acknowledgement and repair of a torn final segment are required. No authoritative JSONL hidden inside a table that rebuild drops.

`EvidenceEvent/1`: event_id, decision_id, event_type (`decision|outcome|policy_transition|deletion`), timestamps, candidate IDs/revisions/scores, chosen action, behavior policy and propensity, registry/config/model/context fingerprints, outcome (`success|failure|unknown`), verifier `{type, id, version, artifact_digest}`, source tier, redaction version, retention class. Verifier types: `deterministic_test`, `external_verified`, `user_judged`, `self_reported`, `inferred`; they are never pooled as equal-quality labels. Server establishes caller provenance; a supplied verifier label does not self-upgrade trust. Unknown outcomes remain unknown, not failures or successes.

Default: no raw prompt, procedure output, secret or absolute project path persistence/export. Context fingerprints use local keyed HMAC for sensitive low-entropy values; export uses fresh scoped pseudonyms. Explicit opt-in raw diagnostic capture has separate retention and consent. Default operational evidence retention 30 days, audit metadata 90 days; these are retention policies, not delivery dates. Operator can reduce/disable retention. Deletion covers ledger, projections, caches, exports still under local management; backups are documented separately with expiry and restore-time tombstone replay. Evidence minimization limits exact query replay; reproducibility uses consented benchmark inputs, not undeclared production prompt capture.

## C7 — Policy state (mandatory owner S07; optional learning owner S10)

S07 owns `policy_store.py` and the minimal mandatory stable-policy API: `register_evaluated`, `approve`, `activate(expected_current, candidate_digest, approval_id)`, `rollback(expected_current, prior_digest)` and `status`. S03 supplies the authoritative storage/lease primitives; S11 supplies CLI bindings. This machinery must function with S10 absent. Stable state path: `candidate -> evaluated -> approved -> active -> retired`; no learning, OPE or canary is required to switch among verified nonadaptive policies. S10 consumes this API and adds shadow/canary transitions for adaptive candidates, with S07 owning subsequent router/config integration and S11 owning subsequent public bindings.

Optional adaptive states: `candidate -> shadow -> evaluated -> canary -> active -> retired`; rejection/rollback records are immutable audit events. Stable incumbent pointer is updated atomically under lease, with expected-current compare-and-swap and durable approval. Store prior policy/config/calibration digests for rollback. Dream can propose candidates but cannot mutate the stable incumbent's scoring state.

A deterministic incumbent provides no support for counterfactual actions. OPE must return `insufficient_support` when candidate policy assigns mass to unseen actions; unknown propensities cannot be imputed. Require verifier-stratified estimates, overlap/effective sample size, temporal holdout and worst-slice checks. No learning promotion is required to release V1. S00 isolation is mandatory; S10 may remain unshipped and disabled with explicit release status.

Canary requires a reviewed manifest specifying assignment seed/unit, traffic fraction, sample floor, primary metric, maximum loss and rollback thresholds before traffic. No live experiments without operator opt-in. Proposed default maximum exposure 5%, anytime-valid sequential loss bound of 2 percentage points, immediate rollback on any trust/compatibility violation. If confidence bounds are not implemented, fixed-sample review only; never repeatedly peek at ordinary fixed-sample intervals.

## C8 — Migration and compatibility (owners S03 / S11)

Dual reader for engram/0.2 and engram/1.0 during V1; writes use explicit target format until migration is approved. Missing legacy constraints do not create fabricated compatibility evidence. Migration preview enumerates changes, information loss and eligibility changes. Preserve original bytes in a versioned backup; explicit apply under lease records resumable journal and stable operation ID. Newer unreadable schema fails with actionable error before mutation. Incompatible downgrade restores the matching pre-upgrade snapshot; it is never simulated by deleting SQL migration rows.

Database migrations are additive/versioned; S03 allocates migration sequence numbers for all slices at integration time. Do not have parallel agents independently claim `003_*.sql`. Use descriptive provisional migrations in lane branches, then serialize through S03 before merge. Restore replays available authoritative current trust/revocation/privacy policy before activating any artifact, using the reconciliation rules below; it cannot infer absent future decisions.

[DECISION] Public V1 schemas are additive within 1.x. Breaking changes require a major version; deprecated fields/commands remain for at least two minor releases and 90 days, whichever is longer. Experimental fields are explicitly namespaced and excluded from stable guarantees. Preserve existing 16 tool names unless a reviewed surface amendment is accepted. SDK protocol support must be demonstrated by pinned host/version transcripts, not inferred from a broad dependency constraint.

Restore reconciliation contract: a backup manifest declares a recovery-point sequence for each authoritative domain; acknowledged records newer than that point are recoverable only from separately retained logs. In-place restore first preserves the live revocation/deletion/policy overlay and its monotonic sequence outside the replaced stores, verifies it, then merges it before activation. A clean-machine/disaster restore requires a separately supplied `RecoveryOverlay/1` export with registry ID, control sequence, deletion/revocation records, policy digest, content hashes and operator provenance, plus an operator-held latest-sequence anchor. Exports use the C10 signature/key format when transferred. Reject registry/key mismatch, stale sequence or missing records. The anchor must be held separately from the old backup; no timestamps alone prove freshness. If either overlay or current anchor is unavailable, import only into a restricted recovery staging area: evidence is not queryable/exportable, artifacts are inactive, routing remains disabled and doctor reports `reconciliation_required`. Operator reconciliation may establish a new policy epoch after documenting unrecoverable gaps, but cannot claim historical deletions/records were recovered. Test valid, stale and missing overlays. Do not promise knowledge of deletions absent from every input.

## C9 — Parallel ownership and handoff

A slice owner owns its new modules/tests. Shared files are edited only by their integration owner: router/config S00 then S07 (including optional S10 integration); policy_store S07, consumed by S10; engram model/parser/writer S02 then S03; core registry/import S04 after S03; migrations/durable storage S03 with S09/S12 serialized; MCP registry/schemas/bindings and CLI S11 (after S12 doctor and S13 packaging requirements are available); eval bench S01 then S14; workflows/pyproject S13; docs authority/index/README S15. Other slices deliver adapter functions and call-site patch notes, not concurrent edits to these files. Sequence is recorded in plan.json locks.

Independent means an agent can implement and verify its owned module against frozen contract fixtures. It does not mean every slice can merge before dependencies. `build_after` gates module construction; `merge_after` gates production integration. S00/S01/S02 can start immediately. Later agents may prepare tests and pure helpers against contract fixtures without claiming integrated completion.

Every handoff includes slice ID, branch/base SHA, upstream dependency SHAs, scope diff, criterion-to-test/result map, migration/rollback notes, unresolved failures and changed public contract fingerprints. Rebase shared-file changes only after upstream merge. No edits to another slice's criteria without a recorded RAMZA freeze amendment. The specs branch is a common planning base, not permission to merge or release runtime code.

## C10 — Bundle trust and local review (owner S04)

[DECISION] Portable registry bundles use a versioned manifest with sorted relative paths, raw-byte SHA-256 hashes, lengths, media types and schema versions. Canonical manifest encoding is UTF-8 JSON, keys lexically sorted, compact separators, no duplicate keys, no non-finite numbers; no Unicode normalization of artifact bytes. Sign those exact manifest bytes using detached Ed25519 signatures. Trust policy pins the public-key SHA-256 fingerprint; private keys remain operator-owned, never imported into Magicite. Make `cryptography` an explicit dependency if the implementation uses it; do not rely on a transitive dependency. OCI releases retain the existing Cosign workflow; bundle signatures and release identity are different domains.

Verify entirely offline against configured public keys and local revocation state; unknown, revoked or expired-policy keys fail admission. V1 need not provide an online transparency service or claim trusted signing time. Key rotation allows explicitly overlapping fingerprints under a new policy revision; revocation immediately invalidates cached local admission. Bound imports to 10,000 entries, 256 MiB uncompressed total and 8 MiB per file by default (configurable, never unbounded); reject archive links, duplicate paths and decompression overrun before extraction outside staging.

Import is staged, validated, then quarantined/pending before local admission. Intake channel establishes origin; an external `.egr.md` declaring `authored` or `verified` cannot impersonate locally authored content. TrustDecision/1 binds digest, signer, source channel, policy revision, scanner revision, actor, decision, timestamp and reasons. Review approval expires on any content/resource or policy change. CLI operations `trust list|review|approve|reject|revoke` use existing durable approval/audit machinery; S04 provides domain APIs and S11 wires commands. These operations do not imply human approval has already been supplied by this planning request.

Body loading is a policy boundary: S11 revalidates C2 plus expected snapshot/content digest before disclosing any procedure. If content/policy changes after routing, return `stale_decision` and require rerouting. Neither a cached selected ID nor a valid signature overrides this check.

## C11 — Index generation and model changes (owners S05 / S03)

IndexFingerprint/1 includes provider, model artifact digest/revision, dimension, normalization, projection version, tokenizer/chunker configuration and schema version. Each indexed entry hashes the complete projected text, including relevant frontmatter and preserved procedure prose; a body-only hash is insufficient. Publish a generation only when every required index row matches its snapshot; build under a new generation ID, validate, then atomically swap the active pointer under the writer lease. Concurrent registry edits either restart/reconcile the generation against a declared snapshot or leave it inactive. Keep the previous complete generation for rollback. Route reads pin one generation; mixed-model vectors and partial builds fail closed. Embedding provider acquisition is explicit and separate from offline routing.
